## 1. 系统概述

**Garlic Claw** 是一个 AI 助手系统，支持多模型对话、插件扩展和设备控制。采用 **pnpm workspace Monorepo** 架构，前端 Vue 3 SPA，后端 NestJS，通过 SSE 实现流式 AI 响应，通过 WebSocket 连接远程插件。

### 1.1 核心能力

| 能力 | 实现方式 |
|------|----------|
| 多 Provider / 多模型 AI 对话 | Vercel AI SDK 统一调用层，支持 OpenAI / Anthropic / Gemini 及兼容协议 |
| SSE 流式响应 | HTTP SSE + 15s heartbeat keepalive |
| 对话管理 | 创建/编辑/删除/重试/停止消息，上下文压缩，图片上传与视觉转述 |
| 插件系统 | 内建 TypeScript 插件 + 远程 WebSocket 插件 + 项目本地插件 |
| 自动化任务 | Cron / Event / Manual 三种触发方式，AI 驱动执行 |
| 工具调用 | 文件读写/搜索/Shell 命令/MCP 工具，支持权限审批 |
| Skill 系统 | 基于 YAML/Markdown 的 Skill 定义，治理策略(allow/ask/deny) |
| 子代理 | 独立会话的 AI 子代理，支持暂停/恢复/中断 |
| MCP 集成 | 完整 Model Context Protocol 支持，stdio 子进程通信 |
| 动态主题 | 壁纸色彩采样 → 光照计算 → Token 管线 → CSS 变量 |
| 背景系统 | 纯色/渐变/图片/视频/幻灯片轮播（5 张，预加载防白闪） |
| 视觉效果 | 点击特效 (5 种) + 屏幕特效 (5 种 Canvas) |

### 1.2 项目元信息

| 属性 | 值 |
|------|-----|
| 包管理器 | pnpm 10+ |
| TypeScript | 5.8+ |
| Node | 20+ |
| 编译目标 | ES2022 |
| 模块系统 | ESM |

### 6.2 Reactive Bridge 模式

解决 Pinia Store 间循环依赖的核心模式：

```
[Appearance Store] ──写入──> themeBaseTokens (ref) ──readonly──┐
[Atmosphere Store] ──写入──> lightingTokens (ref) ──readonly───┤
[Material Store]    ──写入──> materialConfig (ref) ──readonly──┘
                                        │
                              ThemeProvider.watch()
                                        │
                              composeTokens()  // 7 层合并
                                        │
                              scheduleBatch() // rAF 合并去重
                                        │
                              flush() → applyDiff() → :root CSS vars
```

**单写入者原则**：每个 Bridge 只有一个 Store 写入（约定强制，非编译器检查）。读取方通过 `readonly()` 包裹的 ref 访问，防止意外修改。

### 6.3 持久化模式

所有 Store 统一采用：
1. **私有读取函数** `readXxx()` — `localStorage.getItem()` → `JSON.parse()` → 校验回退
2. **私有写入函数** `persist()` / `writeXxx()` — 每次 mutation 后同步调用
3. **初始化恢复** — Store 创建时立即从 localStorage 恢复状态
4. **try/catch 保护** — 防止损坏数据导致应用崩溃

## 7. 主题引擎

位于 `shared/theme/`，是前端最复杂的子系统。

### 7.1 管线架构

```
                 Bridge 层                    计算层                  应用层
            ┌──────────────────┐
            │ themeBaseTokens  │──┐
            │ (from Appearance)│  │
            ├──────────────────┤  │     ┌──────────────┐     ┌──────────────┐
            │ lightingTokens   │──┼───> │  compose     │ ──> │ scheduleBatch│
            │ (from Atmosphere)│  │     │  Tokens()    │     │   (rAF)      │
            ├──────────────────┤  │     │              │     └──────┬───────┘
            │ materialConfig   │──┘     │  7 Layer     │            │
            │ (from Material)  │        │  Merge       │         flush()
            └──────────────────┘        └──────────────┘     applyDiff()
                                                                │
                                                           :root CSS vars
```

### 7.2 Token 分层合并

`composeTokens()` 按以下顺序合并，后者覆盖前者：

| Layer | Token 来源 | 示例 |
|-------|-----------|------|
| 1. Theme Base | Appearance Store 基础色板 | `--background, --foreground, --primary, --accent, --border` |
| 2. Atmosphere Lighting | 壁纸采样光照 | `--atmosphere-1/2/3, --surface-tint` |
| 3. Alias Tokens | Primitive → 语义别名 | `--gc-background, --gc-card, --gc-foreground, --gc-primary` |
| 4. Depth Tokens | 阴影/表面/模糊/Z 层级 | `--gc-shadow-xs..xl, --gc-surface-base..glass, --gc-z-base..tooltip` |
| 5. Material Tokens | 玻璃材质 | `--gc-glass-opacity, --gc-glass-reflection, --gc-glass-blur` |
| 6. Legacy Tokens | 向后兼容别名 | `--shell-bg, --text, --surface-panel` |
| 7. V3 Short Aliases | 新版简写 | `--gc-bg, --gc-surface, --gc-card` |

### 7.3 Token 规模

| 类别 | 数量 | 说明 |
|------|------|------|
| Primitive Tokens | 28 | 基础色板值 |
| Alias Tokens | 28 | 语义化映射 |
| Depth Tokens | 43 | 阴影 / 表面 / 模糊 / Z-index / 交互 |
| **总计** | **~99** | 运行时动态写入 `:root` |

### 7.4 核心文件

| 文件 | 职责 |
|------|------|
| `registry.ts` | Token 定义注册表（Primitive + Alias + Depth 全量声明） |
| `composer.ts` | 7 层 Token 合并引擎 |
| `pipeline.ts` | `scheduleBatch()` rAF 批量 + `applySync()` 同步 + `flush()` 写 DOM |
| `hydration.ts` | **预挂载水合**：`createApp()` 之前从 localStorage 恢复主题到 `:root`，消除 FOUC |
| `theme-base-bridge.ts` | Appearance Store → 基础 Token 的响应式桥接 |
| `lighting-bridge.ts` | Atmosphere Store → 光照 Token 的响应式桥接 |
| `material-config.ts` | Material Store → 材质配置的响应式桥接 |

### 7.5 防御性编程

- **devFreezeTokens()** — 开发模式下 `Object.freeze()` 所有 Token map 和字符串值，捕获意外 mutation
- **computeDiff()** — 只写变化的值到 DOM，减少样式重计算
- **computeTokenHash()** — djb2 确定性哈希用于水合前后验证
- **scheduleBatch()** — `requestAnimationFrame` 合并同帧多次更新，`JSON.stringify` 去重

### 7.6 水合时序

```
hydrateTheme()                          // main.ts 首行执行
  ├── 读取 localStorage["garlic-claw:appearance"]
  ├── 迁移旧 key（如有）
  ├── composeTokens() → :root CSS vars   // 同步写入，无闪烁
  ├── document.documentElement.className = 'dark' | 'light'
  │
createApp() → mount()
  │
ThemeProvider.setup()
  └── startPipeline()                    // watch 三个 bridge，响应后续变更
```

```
(持久化用户配置)                   (当前渲染 Source)                 (判断状态)
     │                                   │                             │
     │ setSource() 写入                   │ 由 Runtime 写入              │ 读 store.source
     │ SlideshowRuntime 驱动              │ BackgroundLayer watch        │ 判断类型/展示
     v                                   v                             v
```

- **`store.source`** — 用户意图的持久化表达（none / color / gradient / image / video / slideshow）
- **`activeResolvedSource`** — 当前实际渲染到屏幕的 source
- **UI 读 `store.source`** 决定显示什么设置面板；**BackgroundLayer 监听 `activeResolvedSource`** 驱动 crossfade

### 8.2 类型定义

```typescript
type BackgroundSource =
  | { kind: 'none' }
  | { kind: 'color'; color: string }
  | { kind: 'gradient'; presetId: string }
  | { kind: 'image'; url: string; meta?: ImageMeta }
  | { kind: 'video'; url: string }
  | { kind: 'slideshow'; photos: Slide[]; intervalSec: number }

type PersistedBackgroundSource =  // blob URL 不持久化
  | { kind: 'none' } | { kind: 'color'; color: string }
  | { kind: 'gradient'; presetId: string }
  | { kind: 'image'; meta?: ImageMeta }
  | { kind: 'slideshow'; photos: { id: string }[]; intervalSec: number }

type DisplayMode = 'fill' | 'fit' | 'stretch'

interface BackgroundAdjustments {
  blur: number       // 0-200
  opacity: number    // 0-200
  saturation: number // 0-200
  brightness: number // 0-200
  contrast: number   // 0-200
}

const MAX_SLIDESHOW_PHOTOS = 5
const DEFAULT_INTERVAL_SEC = 10
const INTERVAL_SEC_OPTIONS = [5, 10, 15, 30, 60]
```

### 8.3 SlideshowRuntime

独立的轮播运行时管理器（存储在 Store 实例上，避免模块级变量）：

- `start(photos, intervalSec)` — 启动定时器，立即触发首张
- `advance()` — **预加载**：`new Image()` + `await img.decode()` 完成后再写 `onResolved`，彻底消除白闪
- `pause() / resume()` — 响应 `document.visibilitychange`（切 tab 暂停，切回恢复）
- `setInterval(sec)` / `updatePhotos(photos)` — 运行时热更新
- `destroy()` — 清理定时器

### 8.4 Blob URL 生命周期

Blob URL 由 Store 全局管理（非瞬态组件），通过 `trackedBlobURLs: Set<string>` 追踪：

- **swapBlobURLs(newSource)** — 新 source 到来时，revoke 旧的 blob URL，track 新的
- **revokeAllBlobURLs()** — clear / resetAll 时全部 revoke
- **持久化恢复检测** — 若从 localStorage 恢复到 `kind: 'image'` 或 `kind: 'slideshow'`，blob URL 必然已过期 → `clear()` + toast "壁纸已失效，请重新上传"

### 8.5 组件结构

| 组件 | 职责 |
|------|------|
| `BackgroundLayer.vue` | `z-index: 0` 全屏固定层，Vue `<Transition name="bg-dissolve">` 实现 3s cinematic crossfade |
| `SourceRenderer.vue` | 根据 `source.kind` 渲染：img / video / CSS gradient / CSS color |
| `EffectRenderer.vue` | 应用 CSS filter 调整：blur / opacity / saturate / brightness / contrast |
| `BackgroundSettings.vue` | 完整设置面板：源类型选择、图片拖拽上传、渐变预设卡片、纯色选择器、幻灯片缩略图管理 + 间隔选择 + 添加/移除 |

### 8.6 图片上传

`useBackgroundUpload.ts` — 拖拽 + 点击，支持多文件：
- 格式校验：JPG / PNG / WebP，上限 20MB/张，8192px 尺寸，最多 5 张
- 1 张 → `setSource({ kind: 'image' })`
- 2~5 张 → `setSource({ kind: 'slideshow' })`
- 幻灯片仅剩 1 张时自动降级为静态 image，0 张时 clear

- **Scoped 隔离** — 组件 `<style scoped>`，Transition 类使用非 scoped `<style>` 块

## 27. WebSocket 通信协议

### 27.1 架构

- **实现库**：`ws`（非 NestJS `@nestjs/websockets`）
- **端口**：23331（可配置）
- **模块**：`PluginWsModule`（`OnModuleInit` / `OnModuleDestroy`）

### 27.2 连接生命周期

```
客户端连接
  │
  ├── openConnection() 创建连接记录
  │
  ├── 10 秒内必须发送 auth:authenticate
  │     └── 超时 → 发送 error + 关闭
  │

  │

  │

  │
  └── 断开: 清理连接 + 标记插件离线
```

### 27.3 心跳机制

- **扫描间隔**：30 秒
- **超时**：90 秒（空闲连接被断开）
- **出站消息刷新**：每 100ms 批量发送

### 27.4 请求/响应关联

`RuntimeGatewayRequestLedger` — 基于 `requestId` 的请求/响应追踪：

- Host call：Plugin 发送 `host_call` → Server 处理 → Server 发送 `host_result/host_error`
- Tool execute：Server 发送 `execute` → Plugin 处理 → Plugin 发送 `execute_result/execute_error`
- Pending 请求：按 `requestId` 匹配回调和超时

## 28. SSE 流式响应

### 28.1 协议实现

使用原生 HTTP Response 写入（非库）：

```typescript
// SSE 初始化
res.setHeader('Content-Type', 'text/event-stream')
res.setHeader('Cache-Control', 'no-cache')
res.setHeader('Connection', 'keep-alive')

// 写入事件
res.write(`data: ${JSON.stringify(payload)}\n\n`)

// 心跳
const heartbeat = setInterval(() => res.write(':\n\n'), 15000)
```

### 28.2 事件类型全览

| 事件 | 说明 |
|------|------|
| `message-start` | 开始生成新消息 |
| `text-delta` | 文本增量片段 |
| `tool-call` | LLM 发起工具调用 |
| `tool-result` | 工具执行结果 |
| `message-patch` | 完整消息更新 |
| `message-metadata` | Token 用量等元信息 |
| `status` | 状态变更通知 |
| `permission-request` | 运行时权限请求 |
| `permission-resolved` | 权限审批结果 |
| `todo-updated` | Todo 列表更新 |
| `retry` | 重试事件 |
| `finish` | 消息生成完成 |
| `error` | 错误信息 |
| `[DONE]` | 流结束标记 |

### 28.3 缓冲事件门 (Buffered Event Gate)

在 `message-start` 之前的事件会被缓冲，防止重连时的竞态条件：

- `synchronizeBufferedTaskStart()` 对缓冲事件与活跃消息快照去重
- 确保重连客户端获得完整的事件序列

### 28.4 重连支持

`GET /chat/conversations/:id/events` — 重新连接正在进行的流：

- 如果有活跃任务 → 开始推送事件流
- 如果无活跃任务 → 检查是否有中断的任务 → 相应处理
